## 2025-03-16 - Defense in Depth at the Platform Layer
**Vulnerability:** Shell execution layer (e.g. `isProcessRunning`, `killProcess`, etc.) implicitly relied on upper level abstractions (CLI, `PortTerminator` core) to validate sensitive parameters (`port`, `pid`, `protocol`). Even though utilities like `executeCommand` use `spawn` arrays instead of `exec`, passing improperly validated parameters (like negative PIDs, unvalidated strings from programmatic calls) could still result in unpredictable shell behavior or unauthorized actions.
**Learning:** Security gaps occur when the lowest architectural layer assumes the highest layer did its job perfectly. In library code especially, boundaries aren't just between the user and the CLI, but also between library functions.
**Prevention:** Enforce defense-in-depth by placing validation logic (`validatePort`, `validatePID`, `normalizeProtocol`) directly at the boundary immediately preceding execution or sensitive operations, ensuring that the inputs are always valid regardless of the code path taken to reach them.
