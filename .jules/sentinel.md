## 2024-03-19 - [Missing Input Validation in Platform Components]
**Vulnerability:** Core functions of platform implementations (`linux.ts`, `macos.ts`, `windows.ts`) did not strictly validate inputs like ports, PIDs, and protocol strings before passing them down towards shell command execution. This increased the potential risk of command injection, unexpected behavior, and DOS attacks through crafted inputs that might bypass validation in higher layers (or skip validation entirely if used directly).
**Learning:** Defense in depth is critical. Even though validators like `validatePort`, `validatePID`, and `normalizeProtocol` exist, they were not applied at the lowest platform architectural layers immediately prior to system commands being interpolated. Relying solely on top-level APIs or CLI inputs to sanitize parameters leaves internal core logic vulnerable if bypassed.
**Prevention:** Implement defense-in-depth by rigorously calling strict validation methods (such as `validatePID`, `validatePort`, and `normalizeProtocol`) directly at the entry point of sensitive platform implementation functions (e.g., `findProcessesByPort`, `killProcess`, `isPortAvailable`, `isProcessRunning`). This ensures a solid baseline boundary and that system-level commands only receive well-formed parameters regardless of origin.
