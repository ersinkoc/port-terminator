## 2025-04-10 - [DoS via Streams]
**Vulnerability:** The `executeCommand` utility used `spawn` to execute platform commands (like `ps`, `lsof`, `tasklist`) but did not impose any limits on the size of the `stdout` and `stderr` streams being buffered into memory strings. This could lead to a Denial of Service (DoS) due to uncontrolled resource consumption (CWE-400) if an attacker or misconfigured command generated an infinite or excessively large stream of output.
**Learning:** Unlike `exec` which natively supports a `maxBuffer` option, `spawn` does not have this built-in limit. When using `spawn`, developers must manually track the size of incoming data chunks and terminate the process if it exceeds an acceptable threshold. The reviewer incorrectly identified a compilation error related to a `timeout` variable name, but `const timeout = setTimeout(...)` was indeed correctly declared.
**Prevention:** Always implement a `maxBuffer` limit when reading from streams in `child_process.spawn`. Keep track of the total bytes received and call `child.kill('SIGKILL')` while rejecting the promise if the limit is exceeded to prevent out-of-memory errors.
